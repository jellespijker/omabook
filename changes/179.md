- A hub's daemon (#179): `omabook hub run` keeps the libraries in a folder chosen once (`--libraries <folder>`) without a window, always on, as their only writer. Everything else on the hub asks it over a local socket, one request at a time, so two computers writing at once take turns; another program that opens a library the hub keeps is refused, and may again once the hub has stopped. `omabook hub session` is what a computer's key will run on the hub, one JSON request a line in and one answer a line out, and `omabook hub status` asks the running hub what it keeps.
- Its systemd units come with the package, one for a person's own user and one for a user of its own (`omabook-hub.service`): started again whenever it stops, its state in its own folder, its secrets in systemd's credentials or a file only it may read (never a keyring), and what it says in the journal.
