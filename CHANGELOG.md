# Changelog

What each release of Omabook brought. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow
`project(omabook VERSION ...)` in `CMakeLists.txt`. What a person sees in the
window is also in the app's own *What's new* (`src/whatsnew.cpp`); keep the two
in step.

Every change that someone using Omabook would notice gets a line under
*Unreleased* in the commit that makes it, with its issue number. A release
moves those lines under its version.

## [Unreleased]

### Added

- A plugin hears when its data came from elsewhere (#126): after a sync with another computer, a pairing or anything else that brings in what it keeps in the change log (`omabook.log`), it is told `log.changed` with `{entities: {entity: [id, ...]}}`, once a sync is done, of its own things alone and never of its own writes; its open view is handed the same as `logChanged(entities)`, so a notebook open on one computer shows the page written on the other.
- A plugin's own kind of book opens in the plugin's view (#125): a plugin that keeps books of its own on the shelf (a notebook) says so with `"formats": [{"extension", "name", "view"}]` in plugin.json or `omabook.format.register({name, extensions, view})`, and opening such a book, by key, click or touch, from search, the command line or the recent books, shows that view with the book (`args.book`) in place of the reader. With its plugin switched off, the book stays on the shelf and it and the reader say which plugin opens it and to switch it on under *Plugins*.
- A lasso for ink (#129): an `InkSurface` has a third tool, `InkSurface.Lasso`. A path drawn with the pen, the mouse or a finger selects the strokes it goes around (those with most of their points inside), shown in a box in `selection.color`, which a plugin sets to the theme's. Drag the selection to move it, or move it with the arrows (with Shift, ten pixels); Delete takes it away, Ctrl+C, Ctrl+X and Ctrl+V copy, cut and paste it, between surfaces too, Ctrl+A selects every stroke and Escape none, and `selection.recolor(color)` gives it another ink. Each is one step of undo and goes out as one ink batch: the strokes removed, and added again as new ones where they went, so that every computer takes it as it takes an eraser's.
- A plugin's files (#131): `omabook.files.writeBytes` and `files.write` keep pictures and sounds under the plugin's `data/` folder as bytes (an ArrayBuffer, a typed array, or base64), and `files.readBytes` and `files.readBase64` read them back; a file holds at most 64 MB and the folder 1 GB (`files.usage()`). `omabook.ui.pickFile({kinds, multiple})` asks you for a file with the desktop's own dialog, and `omabook.ui.clipboard` (the new `clipboard` permission) reads and writes text and pictures, both only right after you did something of that plugin's: ran one of its commands or used its view. Everything under a plugin's `data/` folder now goes to your other computers at a sync, as books do: each file once, by its content, where that plugin is installed too, and a file it removes is removed there; its `settings.json` and what is over the limits stay where they are, and none of it goes into a shared space. `omabook plugin run <name> <what> -` reads the JSON from standard input, for more than a command line holds.
- A plugin can keep its books private (#127): with `"private": ["omanotebook"]` in its plugin.json, its books (a notebook) stay in your own collections and go to your other computers, but nothing of them goes into a shared or published space, also when a collection's rule takes them in, until you let one go. Publishing says which stay out and why, and *Share it…* asks once more before one goes; *Keep it private* undoes it, and a space you publish then takes it back. `omabook spaces private` lists them, `omabook spaces private <book> share|keep` chooses, and `collections share` and `spaces create|sync` say what was kept out. Once said, a kind stays private after its plugin is removed.
- A book's details written into its EPUB (#74), so other apps and e-readers show them: its title, authors, series (as Calibre writes it, and as an EPUB 3 collection), identifiers, tags, description, language, publisher, date and cover go into the package document of the library's own copy, of EPUB 2 and EPUB 3, and the rest of the file stays byte for byte as it was. Ask for it when saving the details (*Write the details into the book's EPUB too*), with `omabook embed <id>` (`--all`, and the MCP server's `book_embed_details`), or at every edit with *Write a book's details into its EPUB whenever they are edited* in the settings (`"write_details"` in config.json). The file you added is never touched; the library's copy is written beside itself, checked, and put in place in one step, and the copy as it came in is kept to put back (*Put the File Back*, `omabook embed <id> --restore`). Your other computers still know the file by the hash it came in with, so a sync doesn't take it for another book. The library's format goes up by one for it (a copy is kept first).
- A plugin is told why it can't have recognition (#133): `omabook.recognize.status(kind, {hosted})` answers `{available, why, message}`, `why` a code (`ai-off`, `no-server`, `hosted-not-allowed`, `hosted-not-chosen`, `no-model` once the server was asked and lacks a model that reads handwriting or transcribes), and `recognize.available(kind, {hosted})` stays true or false and now takes `hosted`. An `InkSurface` says where each stroke is (`bounds()`, `boundsOf(id)`), and its `selection` which strokes the lasso holds (`ids`, and `strokes()` as `recognize.ink` takes them; `select(ids)`), so a plugin never reads the strokes' bytes itself.

### Fixed

- With the AI set to *Off*, nothing is asked of any server (#133): handwriting and speech are no longer sent to the AI server's address (by default Ollama on this computer) nor to whisper.cpp, a book's text is no longer embedded for search by meaning, and `omabook.recognize.available` says false.
- E-readers and phones (#71): Omabook serves the library, or one collection, as an OPDS catalog that e-reader and phone apps (KOReader, Moon+ Reader, Librera, Thorium) browse and download from, read-only and only with its password, never a book a plugin keeps private; and it serves KOReader's progress sync, so KOReader keeps its reading place in step with the library's, matched by the hash KOReader names a file by. Both are off until chosen in the settings under *E-readers and phones*, where it also says where it listens: on this computer, on the tailnet, or (with a warning) on every network. Omabook also syncs reading places with a KOReader sync server elsewhere (`omabook koreader login`, `koreader sync`, or *Sync Reading Places Now*), sends a book to the e-reader mounted over USB in a format it reads (Kobo, Kindle, PocketBook; converted with Calibre when needed) or by mail to a Kindle (*Send to …*, *Mail to Kindle*, `omabook send`), browses other OPDS catalogs (`omabook opds`), and serves from the command line (`omabook serve --reach tailnet`).
- Read a book aloud (#73): R reads from the top of the page with a voice on this computer, Piper (piper-tts and a piper-voices-* voice) or else speech-dispatcher, and nothing is sent anywhere. The sentence being read is marked on the page, the page follows it and the next chapter or page opens by itself, so the place is kept as you listen; R pauses and goes on, [ and ] go a sentence back or on, Shift+R stops, and the bar over the page does the same with a finger or the mouse. How fast and in which voice is in the Aa panel. A server of the OpenAI-compatible API that reads aloud (`/audio/speech`) can do it instead when chosen in config.json's `read_aloud`: only one's own unless hosted ones are allowed, and never while the AI is off.

## [0.1.10.1] - 2026-11-21

### Fixed

- A finger writes on the pages of a PDF or a comic (#134): with D on, a finger moved the page and drew nothing. Now one finger writes and draws until a pen has been used, two fingers scroll and zoom, and once a pen is used a finger scrolls, so a palm doesn't scribble. *Write with a finger* in the writing bar makes it automatic, on or off, and the choice is kept; a handwritten margin note being edited does the same.

## [0.1.10] - 2026-11-21

### Added

- Others' annotations (#85): a space can carry the highlights, margin notes and ink in its books, its new *annotations* part, off until switched on (`omabook spaces annotations <space> on`, `spaces create --parts annotations`, `share --with annotations`, the MCP server's `space_annotations`). Whoever the space reaches sees each other person's beside their own, as far as they have read the book and never further: their highlights fainter under the words with a dotted line, their notes in the margin column under their name, each person in a colour of their own. *Highlights* (Shift+B) switches them off one person at a time or all at once. Their words are shown as plain text, and what is larger than a space takes is left out. A margin note, yours or theirs, can be kept as a fact of a thing in the book's graph, learned where the note is (*Keep as a fact* on the card, `omabook annotations <book> --fact <note> --thing <name>`, `annotation_to_fact`); `omabook annotations <book> --others` and `annotations_others` list theirs.
- Others' annotations go by names and are drawn everywhere (#124): a member of a shared space chooses the name the others see (`omabook spaces name <space> <name>`, MCP `space_name`; one line of at most 64 characters), others' book ink is drawn over the pages of a PDF or a comic in their colour, as far as you have read, their handwritten notes show their ink, and where the window has no room for the margin column their notes are marked in the text and open on a card.
- Book ink (#83): on the pages of a PDF or a comic, D (or *Write* in the bar, or the menu) lets you write and draw on the page itself with a pen, or the mouse; a finger still scrolls and zooms, and a palm is ignored while the pen is near. The bar above the page picks the pen or the eraser and one of four inks, and the pen's other end erases. The ink stays where you put it at every zoom and in every layout, is undone and redone a pause of the pen at a time (Ctrl+Z, Ctrl+Shift+Z), on whichever page it was, and Shift+D puts it away to read the pages as they were. Each page with ink is listed under *Highlights* (Shift+B) with the part of the page it covers, to go there or erase it. It is kept in the change log, a few bytes a point, and goes to your other computers at a sync, where what each of them wrote on a page is all kept.
- Highlights and margin notes on the pages of a PDF and a comic (#115): select a PDF's words as in any book to highlight them or write a note on them (Shift+N, or *Write a margin note* in the menu); a comic's pages are pictures, so there you drag over a panel with the mouse, press and hold it with a finger, or press V and move the part with the arrows (Shift makes it larger or smaller), and choose a colour or *Write a margin note*. A note is marked on the page and opens on a card beside it; E goes through those on the pages in sight. A highlight on a panel is listed under *Highlights* (Shift+B) with that part of the page. Notes and highlights on a PDF's words are found again by their words in another edition, those on a panel by their page, and all go to your other computers. The library's format goes up by one for them (a copy is kept first).
- Search in your notes (#115): Find (/) finds the words in your highlights, margin notes and bookmarks as well as in the book, listed first, and `notes:` in front looks only there; in the library, `notes:harbour` finds the books whose notes, highlights, bookmarks or ink hold the word (`omabook search` too). Where a model is chosen to read handwriting (config.json's `recognition.ink_model`), the book ink on a page is read once the pen rests, by your own servers only and never a hosted one, and found by its words.
- A plugin can record and play sound (#79): `omabook.audio.record({file, onLevel, onStopped})`, with the `microphone` permission, records from the microphone (through PipeWire) into an Opus file under the plugin's `data/` folder, about 4 KB a second of speech and sound for hours, written a second at a time so a recording cut short keeps all but its last second. It says the moment it began, pauses and resumes (each stretch with its own start, so a moment in it is a moment of the day), and how loud it is for a meter. The first time a plugin records you are asked in the window, and while it records a red mark at the top of the window says which plugin, for how long and how loud, with *Stop*. `omabook.audio.play(file, {at, onPosition, onEnded})` plays one from anywhere in it, seeks while it plays, and says where it is ten times a second; `omabook.audio.info(file)` says how long one is. Omabook now needs `qt6-multimedia` and `opus`.
- A plugin can have a view of its own (#77): `omabook.ui.view({id, title, source, key})` shows a QML file of its folder in place of the shelf, or beside the page while a book is open, where it is a pane you drag wider or narrower and lies over the page in a narrow window. Its key, and its entry in the shelf's and the page's ⋯, open it and put it away; so can its own item on the shelf, or the plugin (`omabook.ui.showView`, `closeView`). Backspace goes back within it and then out, Escape closes it, and the plugin's commands for its view work while it has the keyboard, all in the help under *Plugin views*. Its header has the way back, its title and a ⋯ for a mouse and a finger, in your theme, and it can hold an `InkSurface` to write on. A book opened from it is read over it, and closing the book comes back to it.
- Margin notes by hand (#90): with a pen, write on the text (anything that isn't a highlight's line, loop, bar or scribble) or in the margin column beside it, and a margin note is written on the line there, its ink what you wrote. Where there is a margin column the note stands in it beside its line and the pen goes on writing on it; in a narrower window it opens on a card beside the line. The pen's other end erases; a click or a tap on the note shows its tools: undo and redo (Ctrl+Z, Ctrl+Shift+Z), the eraser (X), and its words (W). The ink is kept as strokes and goes with the book to your other computers, where it is found again by its words in a new edition, or listed among the lost notes, as a typed note is. Once the pen rests, the handwriting is read by the vision model of your AI server, on this computer or your tailnet only, unless you ask for its words on a note and allow hosted servers under *Settings*; what is read is searched by *Find in this book*, which now finds margin notes too, typed and handwritten. Erasing a note's last stroke removes it.
- Reading statistics and a goal for the year (#68). `Shift+R` on the shelf (or its list of commands, or the goal beside the number of books) shows a year's reading: the time read, the days read on and in a row, the books finished and how much was read in whole books, by month as bars of the time or of the books, and as a table; every year's beside it; and each book's, when it was begun and finished and how many days and hours that took. For the whole library or one collection. Set a goal of books or of hours there, or with `omabook stats goal 24 books`: the shelf shows how far it is beside the number of books, quietly, and your other computers take it at the next sync. The time is counted while a book is open in the reader, the time away from it (five minutes and more without moving) left out, from this version on; the rest is worked out from what the library already knew. `omabook stats [--year y] [--collection c] [--book id] [--json]` and the `reading_stats` and `reading_goal_set` tools say the same. All of it is counted on your computer; nothing is sent. The library's format goes up by one for the time (a copy is kept first).
- Annotations go in and out (#86): Calibre's highlights now come across in their colours, and a note on one as a margin note on the same words, all found by their words when the book is first opened (a highlight brought in before brings its note the next import). `omabook annotations <book|all>` lists a book's highlights, margin notes, bookmarks and pages with ink, adds a highlight or note on words of the book (`--add highlight --section 2 --words "…"`), changes one's note, colour or name, removes one, and exports them: `--export markdown`, `--export readwise` (the CSV Readwise imports), and for a PDF book `--export pdf --output copy.pdf`, a copy with them written in as standard PDF annotations other PDF readers show (highlights in their colours, notes, book ink). Agents have the same as the MCP tools `annotations_list`, `annotation_add`, `annotation_change`, `annotation_remove` and `annotations_export`. The reading companion, `omabook ask` and `ask_book` are given your highlights and notes up to where you are, never past it, so you can ask what you highlighted about something; like handwriting and speech, they go only to your own AI servers unless you allow hosted servers in the settings.

### Changed

- A book's generated id has one shape everywhere (#128): `omabook list --json` (and `show`, `search`, the MCP server) gives `generated`, the plugin that made the book (`""` for yours), as plugin events and `omabook.library` always did, and `identifiers` on every book; `identifiers.generated` still says it, so scripts that read it keep working.
- The first opening after updating to 0.1.10 brings a library from format 36 up to 39, one step at a time (formats 37 to 39), keeping a copy of it first in `.backups` in the library's folder, as for every format change. An Omabook from before 0.1.10 no longer opens the library, but it does open that copy (#118, #115, #68).
- Find a book's text by what it means, not only its words (#72): "where do they cross the river?" finds where they waded over the ford. Find (/) offers to index the book, saying first where its text goes, and then lists what the words mean after what holds them, up to where you are unless you tick *Past where I am*; *Cancel* stops the indexing. The text is cut in short stretches, each embedded by the embedding model of your own server (Ollama's `nomic-embed-text` on this computer unless config.json's `meaning` names another server or model) and kept in the library, and made again when the book's file changes; nothing goes to a hosted server unless *Index books by their meaning on hosted servers too* is on in *Settings*, and then you are told. Only the books you ask for are indexed, or every one by a setting. `omabook meaning index|update|search <book|all> [--collection c] [--whole]|forget|use` and the MCP tools `meaning_search`, `meaning_index` and `meaning_status` do the same, the whole library within one top-level collection. The library's format goes up by one for it (a copy is kept first).

### Fixed

- Why a book can't be opened, a catalog can't be reached or a file can't be added is said in the desktop's language in the window (Dutch, German, French, Spanish), not in English. Commands keep English for scripts; `--translated` says it in the desktop's language (#70).
- Why the AI couldn't answer (a server out of reach, a key refused, a limit reached, a model it doesn't have) and which model answered in place of a refused one are said in the desktop's language in the window too; a server past its rate limit or quota is no longer asked again on another model because its message mentions one (#119).
- On a desktop whose locale is C or C.UTF-8 the shelf, its groups and filters, annotation exports and the graph's lists sort names as they do in a language (numbers by value, case ignored), and a comic's pages come in order, rather than in byte order (#121).
- A sentence that counts one says it in the singular on the command line: "1 second", not "1 seconds" (#119).
- What a newer Omabook writes that this one doesn't know yet (a reading goal from a later version, say) is no longer lost at a sync: it is kept in the change log, shown nowhere, sent on to your other computers and kept through compaction, and once Omabook is updated it shows, taken in the first time the library is opened (after the copy an update keeps). Until now it was left out and never came, even after updating (#118). The library's format goes up by one for it (a copy is kept first).

## [0.1.9] - 2026-11-20

### Added

- Handwriting and speech can be recognised, for plugins first (#84): `omabook.recognize.ink(strokes)` reads ink through a vision model on your AI server (the ink drawn as a picture), and `omabook.recognize.audio(file)` writes out a recording, each word with its moment, through the server's OpenAI-compatible transcription service (a whisper server), else whisper.cpp on this computer. It runs in the background, one at a time, can be cancelled, and waits while the server can't be reached; what was recognised is kept in the change log by the hash of what was written or said and the model, so your other computers find it without asking again. Nothing goes beyond this computer and your tailnet unless you allow hosted servers under *Settings* (*Recognise handwriting and speech on hosted servers too*) and the plugin asks for it, such as for one notebook. config.json's `recognition` names the models and servers.
- A plugin can let you write and draw with a pen (#78): an `InkSurface` in its panel (`import Omabook`) draws a line as wide as you press, erases with the pen's other end (or the eraser, for a pen without one), whole strokes or the parts it goes over, and ignores your palm while the pen is near; a finger draws until a pen has been seen and scrolls after, and a mouse draws too. Undo and redo go a stroke, or an eraser's sweep, at a time. The strokes are data, a few bytes a point, sent once the pen pauses as one batch that `omabook.log.add` keeps (a notebook's page), and drawn back with `load` and `apply`; a page of thousands of strokes draws within a frame.
- A plugin can keep data of its own in the change log (ADR 0002, #76): `omabook.log.set(entity, id, fields)`, `omabook.log.add(entity, id, set, items, removed)` and `omabook.log.remove(entity, id, set, keys)` write it, signed as you, and `omabook.log.read(entity, id)` and `omabook.log.list(entity)` read it back. It goes to your other computers at a sync and merges there: of a field the later stays, and what two computers added to a set (the strokes of a page) is all kept, with an erasing, or a page torn out, going too. It is never a book, a collection or the graph, stays on your computers (no space takes it yet), is compacted like the rest, and is never sent to an Omabook from before, which would leave it out. A write of more than 64 KiB, or of more than 1000 items, throws; what comes over such limits from elsewhere is refused and said in the sync's summary. `omabook.log(...)` writes the plugin's log as before. The library's format goes up by one for it (a copy is kept first).
- Justified text is hyphenated by the book's language: a long word is broken at the end of a line where its language's rules allow, as LibreOffice breaks it, so justified lines are no longer filled with wide gaps. It uses the hyphenation dictionaries LibreOffice uses (`hyphen-en`, `hyphen-de`, `hyphen-nl` and the other `hyphen-*` packages); a language without one is set as before. *Hyphenate* in the *Aa* panel (the `hyphenation` reading-format option, for every book, a collection or one book) turns it off. The hyphens are only on the page: selected and copied text, search, the graph's marks and the places in a chapter are as they are without them (#69).
- Highlights in five colours (#81): select words (drag, a long press, or V and the arrows) and pick a colour in the menu beside them, or press 1 to 5 while selecting; with a pen, a line under words, a loop round them or a bar beside lines in the margin highlights them in the colour in use, and a scribble over a highlight takes it away. A click or a tap on one colours it anew or removes it. Each colour is readable on light and dark themes and has a line of its own under the words (solid, dashed, dotted…) for readers who tell colours apart less well. *Highlights* beside the page (Shift+B, beside *Contents*) lists the book's highlights in its order, one colour alone if you like, under the names you give the colours ("yellow = important"), with those no longer found in this edition to place again on selected words, and copies them as Markdown. They show in EPUB, FictionBook, Markdown and text books and on a PDF's pages (drag over a PDF's words to select them), travel to your other computers with their colour, and `omabook bookmarks <book> --color <colour or its name>` lists one colour's. Bookmarks no longer list highlights under the contents. The library's format goes up by one for the colour (a copy is kept first).
- A highlight keeps the words it is on, with a few before and after, and is found again by them when the book's file changes: a new edition, a typo fixed, a paragraph put in. One whose words are gone from the book is kept as a lost annotation, for the reader to place again or remove; `omabook bookmarks <book> --lost` lists them. Highlights from Calibre and earlier libraries are found by their words the first time their book is opened, and passages travel between one's own computers with the rest of the annotation (#80).
- Margin notes: select words and write a note on them (Shift+N, or *Write a margin note* in the menu beside the selection). Where the window has room, notes stand in a margin column beside the text, each at the height of its words, stacked where words are close, and stay beside them as the window or the type changes; the column is part of the page's layout, so it never moves the text while you write. In a narrower window, or under fingers, a mark where the words end opens the note on a card. E goes through the notes on the page from the keyboard: Enter edits one where it stands, Delete removes it, and a note left without words is removed. Notes go to your other computers at a sync and are found again by their words in a new edition; those whose words are gone are listed at the foot of the page, to be placed on other words or removed (#82).

### Changed

- The first opening after updating to 0.1.9 brings a library from format 32 up to 36, one step at a time (formats 33 to 36), keeping a copy of it first in `.backups` in the library's folder, as for every format change. An Omabook from before 0.1.9 no longer opens the library, but it does open that copy (#76, #110, #80, #81).

### Fixed

- A book without a cover that the search found by what you know of it no longer has its title run under its author line on the shelf: the title keeps above the author and the band that says what found it (#113).
- The graph's *Between books* view says when it shows part of what there is: "300 of 1,240 connections between books" in its header, with a note over the picture. The connections between the most connected things of the collection's graph come first, rather than the latest, and *Show More Connections* (also under Filter) shows 300 more at a time, up to 900 (#91).
- A thing renamed by hand in the graph of one top-level collection, an author or a theme two collections share, is called so in that collection's graph alone: the others keep the name their books gave it, or one of their own, and the name it had stays one of its names. Search and `knows:` find it there by its new name. With *Knowledge graph: one for the whole library*, a rename is its name everywhere (#110).

## [0.1.8.1] - 2026-11-20

0.1.8 was tagged but its package never built; this is the first release of what 0.1.8 brought.

### Fixed

- A relation of no book between a thing of a top-level collection's graph and one that every collection sees (put in by hand before collections had graphs of their own, or a plugin's world) is seen again in that collection's graph, and counts there in the order of the graph's window. Such relations were in no collection's graph once one of their ends was met in a book: Storyteller's plan lost a person's ties to the rest of the cast as soon as a chapter mentioned that person (#112).
- A plugin's world (Storyteller's story world and plan) is read and written whole, whatever top-level collections the books its things were met in are in: a sequel or a branch, whose world was met in the first story's book too, can go on when the two books are in different collections, and a plugin is told of the worlds of every collection, not only of the one with the most books. On the command line, `omabook graph show`, `find` and `add` with `--scope` read and add to a world without `--collection`, and `omabook graph scopes` without it lists the worlds of every collection (#112).

## [0.1.8] - 2026-11-20

### Fixed

- A book whose details are the same on two computers is no longer reported as taken at every sync from one of them: the details taken keep their time to the clock's count within a second, as the other computer's log says it, so a cover set in a second the clock ticked in more than once is newer there no more. And both computers compare a book's details as their logs say them, so a book is undecided from both sides or from neither (#106).
- A book's graph, its spoiler cut and the graph palette's list of books no longer read the whole knowledge graph for each book: the palette's list took over a second on a library of 1,500 books, and ten times that on one of 15,000 (#99).
- The graph centred on a thing in a large library counts what is around it at once: four steps out took over a second on a library of 1,500 books, and now takes a few hundredths of one (#100).
- An answer from a model that wraps it in HTML-like tags (`<panel>…</panel>`, `<div>`s, a stray `<span>`) is shown without them: in the reading companion, the library's answers, `omabook ask` and the MCP tools that answer questions, whichever AI answers. Markdown stays as it is, and so does a tag written in a code span or a code block. The companion and the librarian are also told to answer in plain text or Markdown (#105).
- What is written by hand on a thing two top-level collections share, a summary, another name or a relation, is seen only in the collection's graph it was written in, and a relation two collections' books both tell keeps each book's note: one collection's book or hand no longer changes what the other reads of it. - A computer that a sync paired into another person keeps what it was in spaces as the person it was: that person's key is kept (`former-persons/` in your Omabook data folder, readable only by you), so an invite sealed to it still opens; in a shared space where it was a writer it makes you, as you are now, a writer, and goes on writing; where it was a reader it goes on reading; and a collection it shared stays the same space, now yours as you are, so those who follow it take what is new (#50).
- `omabook sync`, the window's sync status and the sync log now report knowledge graph changes taken and sent (#31).
- Knowledge graph sync now settles in a single sync when two libraries call the same thing by different names, without merging separate local things that share another name (#31).
